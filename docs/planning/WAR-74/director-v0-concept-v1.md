## 1. 目标、层级和边界

### 1.1 方法层：通用单场景导演规划

输入一段**已确认的单场景剧本与可用创作约束**，提出可解释、可交互修订的导演方案，按因果关系从“观众需要看到/理解/感受什么”落到 Beat、Blocking 和 Shot Plan。面对需要视觉证明的目标，要求每镜说明其**信息任务、观众可见证据判据、方案与验证状态**。不预设几个 Agent、不要求每段固定镜数、不以更碎的镜头等同更好表达。

v0 **不负责**长篇小说改编与完整剧本创作、角色/场景资产制作、原生 Storyboard 图片、自动观看理解评分、完整的物理仿真、视频生成/剪辑/局部重生。上述能力可在后续 Canvas 和生成工作流按实际价值接入。

### 1.2 适配层：首个 H3 Ref2VA 目标

导演 Scene Plan 可以规划一个完整的 30–40 秒甚至更长的单场景，不被一次 H3 视频上限反向切碎。交给 H3 的**执行单元**另行选取，承接上下文、状态、对白与镜头责任。

已确认的**项目设计目标**：三张实体参考图（人物/场景按职责）、12 秒为正常可用长度，执行单元**允许设计至 15 秒**；5–8 秒仅为历史实验口径，Beat 数和 Shot 数都不设 1–3 或固定四镜硬上限。**这不是已独立核证 H3 15 秒直出成功率的结论**。引用与 Add Guide、关键帧/Camera Tree、跨视频持续生成、具体 prompt 生成策略由适配/实施阶段决定；本轮不默认加入 Add Guide。

三种对象必须分离：**Beat（叙事变化）≠ Shot（观众信息与摄影覆盖）≠ Video Execution Unit（具体模型的一次执行/交付）**。

## 2. 唯一事实依据与四种薄产物

设计模型：**Story Basis（共同依据）＋ Director Intent / Beat / Blocking / Shot Plan（四种薄产物）＋贯穿 Review**。

**Story Understanding** 是对已有剧本进行事实整理和解释的工作，不强制生成另一套独立事实表。Story Basis 保留源剧本和经用户确认的创作约束，凡是模型提出的潜台词、临时空间尺寸或拍摄假设不得静默升级为故事事实。

| 产物 | 最小必需语义 | 主要职责与禁止越界 |
| --- | --- | --- |
| **Story Basis** | 剧本来源与原文/对白、人物及关键道具、已确认动作与知情顺序、关键空间/资产约束、未知项和来源性质 | 事实与用户已确认意图的唯一权威；下游引用，不复制四份；修改已批准事实需用户明确授权 |
| **Director Intent** | 观众应知道/暂不知什么、注意谁/什么、情绪或潜台词目标、重要揭示时机/顺序、不能违背的约束和依据 | 决定**为什么表达**；不硬编码所有镜头/焦距；区分作者原有意图与模型新增解释 |
| **Beat** | 事件/因果、可见行为及对白范围、人物/道具/观众信息的状态输入输出、节奏与意图关联 | 决定**故事发生了什么变化**；不强制一 Beat 一 Shot，不预先绑定固定 H3 时长 |
| **Blocking** | 所关联事件、人物与道具起终关系、动作路线与交互、眼线/注意力、空间条件、物理与可见性的待验证假设 | 决定**表演如何落实**；世界方向与画面左右分开，物理视线与人物实际注意到分开；文本设计不等于真实几何通过 |
| **Shot Plan** | 对应意图/Beat/Blocking、逐镜信息任务、画面主体和构图/机位/运动/时间/切点、覆盖动作对白、相邻连续状态、**观众应获得的可见证据/判据**、风险/版本/决定状态 | 决定**摄影如何向观众交付信息**；不能只写“可见”而没有可检验目标，也不能静默改变剧情状态 |
| **Review（横切）** | 检查项/证据层级、影响对象、风险、建议与实际修订区别、复检、用户批准/接受例外与未证项 | 不建立第六份事实账本；为不同产物提供跨层一致性和修改反馈 |

上表是**语义层契约**，并非全部字段都必填、必须分别成独立文件或有固定数据库列。简单动作允许短写，复杂遮挡/交接才展开必要细节。

## 3. 共用引用和信息优先级

- 关键意图、事件、动作决策、镜头及必要状态应有**稳定引用**，支持从 Shot 回溯它服务的观众任务与事件；拆分/合并时保留来源或映射。
- 每个关键主张区分：**剧本/用户确认事实**、**模型候选/导演建议**、**实验或验证结论及其覆盖范围**、**未知或假设**。来源与版本不等于可信度分数。
- 重要状态至少区分：**世界事实**（例如钥匙裸露）、**视线几何可见**（有无遮挡）、**人物注意/知情**（有没有发现）、**观众画面可读/理解**（是否看清）。四者不能自动互推。
- 事实和创作硬约束不可被 Shot 或 Blocking 偷偷覆盖。模型可以提出“请求上游修改”，但不自动批准。
- 不预先复制 Canvas 现有 graph/asset/task，也不为这套引用建立完整人物/道具实体数据库。**WAR-35/WAR-52 再决定具体 Schema、ID、Join 与版本映射**。

## 4. 工作步骤与审阅关口

1. **Story Understanding**：核对已确认剧本/对白、事实、知情差与未知；模型解释标候选。
2. **Director Intent（审阅 A）**：说明观众视角、信息释放和情绪焦点；用户确认关键导演方向或选择备选。
3. **Beat**：分出有因果与状态变化的叙事段，建立 state-in/out，不预定镜头数。
4. **Blocking**：落实人物与道具动作/眼线/位置，记录需要物理/空间实证的假设。
5. **Shot Plan**：依据 Intent、Beat 与 Blocking 选择镜头信息功能、构图/节奏/剪点，写下观众可见证据判据和上游依赖。
6. **Check / Review（审阅 B）**：对决定性不变量和开放风险复检，展示变更影响、保留/退回/有条件批准。

A、B 为**默认两处用户审阅**；Beat/Blocking 允许展开细看。遇到原剧本解释重大分歧、硬性状态冲突、关键尚未确认的创作选择，必须提前回到用户，而不是等到 B 才呈现。Review 贯穿各阶段，不是最后才首次检查。

## 5. 局部修改、依赖复检与版本

核心原则：**局部优先，必要时跨层，差异必须可见**。

1. 接收用户反馈，确定意图修改范围和原有批准约束。
2. 用稳定意图/事件/状态/镜头引用定位直接影响对象，并向必要的相邻镜头、全场时长和后续状态延伸复检。
3. 产生**候选修改**，不覆盖上一已批准版本；区分“想修改什么”和“模型实际改了什么”。
4. 按事件/信息任务对齐前后版本，列出目标修改、伴随改变、超范围变化、镜数/时长/状态和硬约束冲突。
5. 执行可确定检查；风险/未知不得伪称实测。
6. 由用户选择接受、部分接受、退回或撤销；只有实际应用且复检的产物才改变最终审核状态。

影响规则：改 Intent → 复核相关 Beat/Blocking/Shot 与邻镜预算；改 Beat → 复核相关行为与后继状态；改 Blocking → 复核依赖镜头、视线和连续性；改 Shot → 复核观众信息交付、邻镜/时长与已确认状态。改 Shot 若要求改变角色知情或故事因果，必须**上行申请剧本/Intent 修改**。

**无需保证一次模型调用绝对局部**；WAR-73 配对文本回放证明存在关注点变化与非目标镜头连带修改，不能证明必然因果或稳定复现。此处要求“呈现并审核真实差异”，不是宣称已有局部生成引擎。

## 6. 风险、证据等级与批准口径

| 级别 | 如何处理 | 阶段批准 |
| --- | --- | --- |
| **确定性硬冲突** | 比如对白遗漏、知情顺序违背、物件复制/归属冲突、明确时间/状态不变量不一致；须修订或由作者正式改变约束 | **阻塞**，不得以用户“接受未知风险”掩盖 |
| **规划风险/有条件假设** | 动作时长、复杂交接、动态轴线、推定遮挡、摄影选型等；记录理由、可能影响、候选修复 | 可在用户明确接受开放项后**有条件批准** |
| **媒体与观众未证项** | 真实人物几何、画幅内可读性、表演是否自然、观众理解、H3 直出质量 | 留给 Canvas 画面审阅/未来媒体验证；在此不声称已通过 |

最小闭环：**发现 → 候选策略 → 实际修订 → 复检 → 确认解决或接受未证**。提出修复建议不等于已经更新主计划；红/橙风险等级不是 H3 真实成功率，也不能为求绿色擅自降分。

“导演方案阶段通过”只表示语义、文本状态与适用计算检查在其证据范围内通过，或用户明确接受部分开放风险；**不构成生成权限、画面质量或 H3 模型能力已验证**。

## 7. D《错过的钥匙》纸面契约示例与质量边界

以冻结 B2（文件移开，K 露出，观众先见）和 B3（蓝夹再次遮 K，周只察觉遮挡）为例：
- **Story Basis**：一把钥匙在被拿起前留在 K；先露/再遮；观众知情、林未注意、周未见是**作者确认意图**，不算模型新创。
- **Intent**：观众先得到关键信息，之后看到答案再次被遮住。
- **Beat**：文件遮→移开→露出→蓝夹盖住；世界状态与人/观众知情分别记录。
- **Blocking**：林移文件/目光不在 K；周接近、目光只落蓝夹；几何遮挡为**未证假设**。
- **Shot**：原 Shot02 为 40mm MS 6s，Shot03 为 85mm ECU 6s；必须写出观众要获得什么画面证据，不能以“镜头说观众可读”代替可读性检验。
- **Review**：WAR-72 简化几何/Blender 曾发现 Shot02 钥匙在 960×540 代理画面约 27×9px 且部分遮挡、构图不足以证明观众先发现。这不是“所有 40mm 必失败”，也不是任何真实观众实测结果。

思想检验：若只改 Shot02 焦距，优先复检该镜的信息覆盖、动作、构图与邻镜；若要改“周先发现钥匙”，先与已确认作者意图冲突，不能只下游改镜头。完整纸面依据在 `d-b2-b3-paper-contract-walkthrough.md`；原 WAR-65/72 证据保持冻结。
