# WAR-74｜Canvas Lab Director Skill v0 阶段语义契约草案

状态：**讨论草案，非已批准实现规格**。日期：2026-11-13。Linear：[WAR-74](https://linear.app/xiangshushu/issue/WAR-74)。设备：Eric；项目根目录 `/home/sean/projects/canvas-lab`。此文件是本轮详细设计提案唯一工作正文；Linear Issue 负责状态、确认决定和索引；不修改原始 Skill、不进入编码/视频/Canvas 实操。

## 0. 已确认决策与待议内容

已确认（用户在 2026-11-13 讨论中决定）：
- v0 范围：**通用单场景导演方法 + H3 短片段适配**，两者分层；不把场景规划限制在 H3 单次时长内。
- 默认两处审阅：A 导演意图，B Shot Plan + 风险；Beat/Blocking 可按需审阅，重大事实冲突/未决约束额外暂停。
- H3 不设 8 秒硬上限：12 秒为正常设计长度，首个适配目标允许最长 15 秒；历史 5–8 秒和 1–3 Beat 不是导演方法硬上限。
- 允许导演规划**带明确、可追踪且由用户接受的未证风险**完成阶段验收；实际画面/观众理解/H3 视频需在后续 Canvas/媒体验证。已证实的剧情事实、对白和关键状态硬冲突不得作为风险放行。

本稿仍待用户确认：下述最小字段、引用粒度、变更传播/复检口径、H3 执行单元分界与发布状态；不预先决定 Agent 数量、JSON Schema、UI 或编译器实现。

## 1. 模型：Story Basis + 四种产物 + 贯穿检查

- **Story Basis（唯一事实依据）**：原剧本文本/对白、角色/场景/道具身份、创作人确认的剧情不变量、已知空间和资产、明确未知。模型解释、导演方案和临时空间尺寸**不回写**为剧本事实。
- **Director Intent（为什么）**：观众信息/注意力/情绪与导演选择，不先硬编码机位。
- **Beat（发生什么变化）**：有因果关联的叙事事件、动作和前后状态，不等于 Shot。
- **Blocking（如何表演）**：动作路线、位置、视线、道具交互、可见性要求和待验证假设；不证明真实物理成立。
- **Shot Plan（如何呈现）**：每个镜头的叙事任务、覆盖事件、摄影选择、时间/剪辑、前后连续性及取舍。
- **Review（横切机制）**：跨层检查、风险说明、候选修订、实际修订、复检和用户审阅；不是第六套事实账本。

候选原则：共用故事依据与关键对象引用，**不在四个产物重复维护彼此独立的事实副本**。如果一个机制本身就能推断，不为它制造完整实体系统。

## 2. 全部产物共用的最薄元信息（语义要求，而非 Schema）

| 要求 | 用途 / 限度 |
| --- | --- |
| 稳定引用标识 | Intent / Beat / Blocking 决策 / Shot 的条目能互相定位；同功能修订保持 ID，拆并时保留来源关系 |
| 引用依据 | 指向原剧本段落或已确认约束，以及所依据的上游意图/事件/状态；不复制多个事实源 |
| 来源性质 | 区分“作者/用户确认”“模型候选”“测试假设”“实际检验结果/未知”；**不用伪精度置信分数** |
| 批准状态 | 方案候选、已批准、待复检或被否决；局部修订不自动将其它对象改成“已批准” |
| 版本与差异 | 保留可比较的前后版本、稳定引用及变更范围；暂不强制每个字段单独版本化 |

注：这些是设计目标，不表示四种产物都必须有五个重复的数据库列；实际 WAR-35/52 契约设计时再决定合理形式。

## 3. 四种核心产物的最小必需信息

### 3.1 Director Intent

最小：**观众信息任务（应知道/暂时不知什么）**、注意力落点（谁/物/关系）、情绪或潜台词目标、关键时机/顺序、不能违背的事实与软偏好、依据/确认状态。关键意图应能回指来源事件/剧本位置；可以先按事件命名，再关联 Beat，不必先有 Shot。

不要求：镜头景别、焦距、剪点、完整摄影机运动；这些属于下游候选。
默认审阅 A：用普通创作语言确认“观众什么时候理解什么、关注什么、想获得什么体验”；未决关键解释须列为可选方案，不能偷偷确定唯一答案。

### 3.2 Beat

最小：**叙事事件/转折与因果**、前后可追踪状态（人物/关键道具/角色知情及观众知情）、必须发生的可见动作/对白范围、与 Intent 的关系、建议节奏或可用时间范围（可暂未定）。

不要求：固定 Shot 数、具体机位、完整资产表或给每个 Beat 预设一个视频片段。

状态应当使用关键事件/状态的共享引用；Blocking 负责具体落实，Shot 负责选取可见证据，不能各自产生互相矛盾的道具归属账本。

### 3.3 Blocking

最小：**关联 Beat/事件**、人物/道具的起止位置或相对关系、动作路径/交接、目光/注意力、关键可见性和遮挡要求、空间/物理假设与未验证项、对 Shot 的可拍性限制。

简单表演允许简写；复杂动作才展开站位和阶段。世界位置、镜头画面左右和人物主观“注意到”是三件事，不得混同。没有场景几何时不能声明“摄影机一定能看到而角色一定看不到”。

### 3.4 Shot Plan

最小：**关联 Intent / Beat / 已约定动作状态**、镜头信息任务（为什么拍）、覆盖事件与对白范围、主体/景别/机位/运动建议、开始结束时点或时长、剪切/相邻连续关系、从画面获得的证据、风险/替代方案及批准状态。

Shot 数由叙事/表演需要决定，Shot 与 Beat 不是一一对应；镜头设计中提出的空间调整需作为 Blocking 候选上行，不能直接更改已确认剧情。摄影选择可先采用“关系/近景/道具特写”等语义，精确焦距仅在有理由和证据时填写。

## 4. 检查层的三种证据性质与放行

1. **可确定检查**：台词/说话人是否完整、事件顺序、状态转移/唯一物件归属、时间区间/总长、已批准硬约束、依赖是否过期；发现硬冲突必须修订或由作者明确变更上游约束。
2. **规划推断风险**：演员走位/人体动作、轴线/眼线、道具精确交接、镜头复杂度、未测的对白时间、景别切点等；标明原因与可选方案，不把风险颜色当成功率。
3. **媒体验证未知**：真实几何可见与物件像素可读、观众理解、H3 的实际剪切/动作/音画表现；在 Canvas/视觉/视频环节验证，现阶段只留下入口和风险类型。

最小处理轨迹：发现 → 提出候选 → 是否真正应用 → 复检 → 用户批准/接受未证/退回。**接受未证风险**可以让导演方案进入下一环节，但不能将“媒体验证未知”改为“已通过”，也不构成 GPU 授权。

## 5. 局部修改和失效传播（候选）

| 用户修改位置 | 优先定位与重新考虑 | 通常不应自动重生成 |
| --- | --- | --- |
| Director Intent：观众关注、揭示时点 | 对应事件/Beat，相关 Blocking 的表演/视线，覆盖事件的 Shot，以及相邻剪点与全场时间预算 | 无关 Beat/Shot、剧本事实 |
| Beat：事件、前后状态、时序 | 关联 Blocking 和 Shot，后续依赖该状态的 Beat/Shot，角色/物件状态链 | 不相干场景或不依赖的镜头 |
| Blocking：站位、动作或视线 | 引用该段动作/位置的 Shot，相关剪辑/轴线/可读性；若与已确认事实冲突则升级报告 | 已确认 Intent 和剧本事实 |
| Shot：构图、机位、时长、切点 | 镜内任务完成性、邻镜状态/轴线、全场时长、已批准预算及 H3 分组候选 | 无关 Beat/Blocking；除非实际要求修改动作 |
| 风险确认/接受 | 对应开放项、下游交接提示和审核状态 | 原始风险证据、剧情与镜头内容 |

**变更协议**：确定“意图修改范围” → 生成候选 → 按事件/稳定 ID 对齐原版与新版 → 展示意外连带变化、镜数/时长/状态变化 → 局部及全局必要不变量复检 → 用户接受/撤销/选择性保留。受影响项可标待复检，不因一次模型重写而自动升级为批准。无法限定范围时透明提示“需扩大检查”，不保证绝对局部性。

### 例：C《没说出口》的“关注许”

A/B 文本研究中，关注点改动伴随许回头无对白反应镜 2s→4s、全场 30.5s→33s，其他 Shot/切分也发生变化。v0 应把“许的注意力/反应镜”列为预期差异；把全场预算和其它 Shot 改动列为连带差异，明确交用户取舍。**单次文本回放不能证明规律性因果或观众效果。**

### 例：D《错过的钥匙》的“先看见钥匙”

Intent 要求观众先发现钥匙、周此前不能见；Beat 记录文件移开及钥匙露出；Blocking 描述人/钥匙/文件/视线；Shot 负责钥匙在画面中可辨。WAR-72 发现 40mm MS 的钥匙在代理构图中约 27×9 px、部分遮挡；这属于**文本表达目标与实际可读性未闭合**。可以带明确未证风险交接视觉审阅，但不能写“观众识别已通过”，也不在本任务重做 Blender。

## 6. Scene Plan 与 H3 执行单元

- Scene Plan 是完整单场景的导演决策，不按 H3 单次视频上限直接切 Beat/Shot。
- 初期 H3 执行单元：三实体图 Ref2VA；12s 为正常设计长度，最长允许 15s；5–8s 是旧研究样本而非硬限。Beat 数量和 Shot 数量不按 1–3 机械限制，由叙事和模型适配风险决定。
- 执行单元选择应携带起终状态、动作/对白范围、Intent 与 Shot 覆盖、必要上下文、参考职责及尚未验证的媒体风险；不能把“拆成若干 H3 单元”视为已解决跨视频连续性。
- 视频编译/模型能力限制由 WAR-38 等后续契约及验证处理；当前不生产 H3 Prompt。

## 7. 本轮待用户审阅的取舍

1. **共同事实引用**：是否采用“Story Basis + 四种薄视图 + 稳定事件/状态引用”，而非四套各自完整表格？建议采用。
2. **字段层级**：是否接受先只确定语义上的“最小必需信息”，暂不规定正式 JSON/结构？建议采用，交 WAR-35/52 后续设计。
3. **修订与风控**：是否接受“局部优先、依赖复检、显示超范围变化、用户才可接受未证”，不追求完全不波及其它镜头？建议采用。

一旦这三项确认，下一轮可设计**一次从 Intent 到 Shot 的小型纸面契约示例**（只使用已冻结研究事实，不运行 LLM/Blender/GPU），验收字段是否足够、是否冗余，再冻结 WAR-74 概念规格并决定是否转入 WAR-35 等任务。**新对话提醒点**：WAR-74 概念设计收口、准备切换 WAR-35 Schema/具体实现规划时。
