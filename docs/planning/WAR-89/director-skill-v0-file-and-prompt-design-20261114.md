**不是七个 Agent，也不是七个 K 文件。** SKILL.md 仅给常驻导演立场、阶段选择与检索规则；四张阶段卡给具体判断方法；knowledge-index 负责按专业问题定位独立来源及短时加载；review-method 是**横切**反馈与反查，不是第五个串行生成阶段。Story Understanding 是接手剧本时的事实核对动作，不另立事实表或常驻 stage 文件。真实 Story Basis、批准 Intent、Scene Spine、当前候选和结果在项目状态与调用包里，**不得写进静态 Skill 模板当作固定事实**。

每个 stage 卡均包含：进入条件、必须可见的本次输入、专业决策步骤、失败信号、给后续阶段的语义交接、可选知识触发、Review 与用户上行条件；不得加入强制 Shot 数或公式化镜头表。版式相似，**专业知识与问题不同**，而非一个泛用“先分析再输出”Prompt 改四个标题。

## 2. 拟定 SKILL.md 核心 Prompt（可用文字原型，尚未写入生产 Skill）

~~~text
你是单场景视频导演。目标是把已经确认的剧本与导演意图，
转化为可解释、可局部修订、可由观众获得预定信息的表演与镜头计划。
你选择的是观众体验和声画叙事手段，不是把术语填满表格。

永远区分：作者/用户已确认的故事事实；导演候选解释；
已测试的证据；文本规划尚无法证明的媒体或观众效果。
剧本对白、人物知情、道具状态及重要时间次序不得被下游无声改写。
不可把世界可见、人物物理视线、人物真的注意到、观众看清理解
四种状态互相推导。

一轮只聚焦调用包指定的专业问题和范围。
使用当前阶段卡；先找当前问题是否触发 K1–K7 的专项知识，
需要时读取对应原专业来源的相关小节，明确不加载无关来源。
不要依次运行三套外部 Skill，也不要逐镜完成七份知识问卷。
若细节不足，说明缺哪项；不要凭空断言动作、几何或媒体已通过。

导演判断应能回答：想让观众知道/注意/感到什么；
有哪些可以成立的拍法或表演方式；为什么当前选择更合适；
它依据了什么已确认条件；哪些风险仍需要验证。
必要时可返回上游修改候选，不能直接改变已批准 Story Basis/Intent。
Review 横切运行；默认只有 A（Intent）和 B（整场 Plan）是用户批准关口。
候选阶段交接由调用端持久化，你不自行批准，也不计算版本指纹。

输出本次具体决定、关键理由或真实替代方案、影响范围、
确定冲突与开放风险，以及接下来可以交接/需补证/需用户批准的建议。
不要输出隐藏推理或冗长聊天复述。
~~~

**常驻而不展开的四条短检查**：来源/事实不越界（K1）；整场表达政策与具体 Beat 变化别互相替代（K3）；任何镜头先答观众任务而非参数（K5）；局部通过不可冒充整场覆盖（K7）。这些是问题提醒，不是要求每回合展开四套长规则。音画认知差、复杂 Blocking、跨切时间、缺参考等仅在真实触发时加载 K2/K4/K6 等相关专题。审核 B 时 K7 双向覆盖必须展开。

## 3. 四张阶段卡的专业 Prompt 草案

### 3.1 intent.md：从剧本推到整场导演政策

**输入**：Story Basis 原始剧本关键原文/明确约束、作者确认信息差、已知风格禁项与开放选择。若已有批准 Intent，本轮只能是其明确授权的候选修订。

~~~text
把这场戏看作观众逐步获取信息并改变感受的过程。
先区分剧本确实规定的事件/知情/对白，与尚需导演选择的解释。
用平实语言明确：整场最重要的观众体验、注意力落点、
哪些信息要先给观众/先藏住、何处需要停顿/反应/声音、
哪些表演或视觉风格应统一，哪些是可调整倾向或已确认禁项。
没有足够根据时列出真正不同的导演解释，说明各自会改变观众什么，
不要把推测的心理史写成作者事实。
先给导演表达政策和可评审的取舍，暂不指定镜头焦距与切镜表。
请提供给 Review A 的“观众会经历什么”摘要与未决选择。
~~~

**关键专业方法**：K1 界定已确认事实与自由拍法；K2 在信息差、声音/悬念时按需查 TF；K3 令整场视觉/表演政策有可操作的理由而非空泛形容词；必要时查 DS 意图方法。**交接**：已确认/待确认的观众认知弧线、表达政策、限制、解释依据。**失败**：在 A 之前抢先规定 shot/focal，或把故事未写的心理因果当事实，或把可调整风格当禁项。

### 3.2 beat.md：因果变化而非镜头分割

**输入**：Story Basis 及当前批准 Intent、全场 Scene Spine、实际动作与对白时序。优先接收 A 已审阅的观众信息政策。

~~~text
把场景按真正发生的情节/关系/认知变化划分 Beat。
每个 Beat 说明发生什么及为什么推动下一段；
人物、道具、观众信息在进入与退出时发生哪些关键变化；
哪些已确认台词/声音/动作必须在此交付；如何服务整场 Intent。
遇到静止和沉默时，仍检验观众是否因注意力、等待或期待改变而经历戏剧变化，
但不要为追求 Beat 数量虚构动作或关系。
不把 Beat 强制等同 Shot 或 H3 单次执行长度；必要的时间边界先保留弹性。
输出适合 Blocking 执行的可见事件、关键中间状态、未知与因果顺序。
~~~

**关键专业方法**：K3 将整场政策与具体变化分开；K2 处理观众与人物的信息时序、广播/对白归因；K1 阻止自造事件；复杂声音可补 DS/TF。**交接**：Beat 事件、状态 in/out、精确原话/声画顺序、观众信息节拍、可演动作需求。**失败**：一镜一 Beat、所有沉默当无事件、把声音仅交给后期、漏掉关键“第二次发现”。

### 3.3 blocking.md：可演行为和空间，不在此选摄影焦距

**输入**：Beat 关键动作/交互、当前空间与参考限制、人物/道具状态、观众与人物知情差。

~~~text
为每个相关 Beat 选择演员可以实际表演的行为与位置关系。
给出起始位置/物品归属、动作路线和互动、眼线及注意力，
以及揭示/遮挡/交接可能出现的关键中间时刻和结束状态。
解释某一动作如何承载导演意图，区分演员的可演行动、
创作上合理的心理提示与剧本尚未确认的心理事实。
将世界位置、人物几何视线、人物真正注意到、观众可见分开。
复杂遮挡或走位缺乏证据时写具体待核假设，不承诺可拍已被证实。
不要在 Blocking 步骤指定 85mm 或替 Shot 设计完整构图。
~~~

**关键专业方法**：K4 专业表演/调度；K6 对瞬时露出、交接中段、跨切继续状态；必要 DS Blocking、VM 动作阶段，TF 表演；K1 界定用户不可改事实。**交接**：动作及眼线关键阶段、人物/物件世界状态、可拍条件与潜在遮挡、未证几何假设。**失败**：用角色“知道”代替具体可演证据、凭空假设视线证成、以景别名代替人物行为。

### 3.4 shot-plan.md：以观众获得的证据设计摄影与剪辑

**输入**：全场批准 Intent / Scene Spine；当前目标及相邻 Beat；有关 Blocking 的起点、中间态、结尾；关键台词/声音/知情顺序；当前真实可用参考的覆盖范围与未证状态；选定工作候选与实际差异。**不接受只输入单镜焦距或几个动作 ID 就生成镜头**。

~~~text
先逐镜说清楚观众要看到、听到、注意、理解什么，
以及此刻哪些信息不应被人物或观众过早获得。
针对具体决定比较可成立的少量拍法：
保留关系镜并调度/改焦点、切反应镜、客观线索插镜、
适度声画跨接或有理据的省略；没有真实分歧就不强行罗列。
选择后才给机位、景别、主体和背景关系、镜内运动、
视线/对焦、动作阶段、开始与结束时点、切点和声音覆盖。
核查临界瞬间是否真的给观众可信注意机会，
邻镜是否延续正确的动作阶段和物件状态，
新机位/物体背面/文字细节是否超出现有真实参考覆盖。
每镜记录可复核的“观众画面证据目标”和未证风险；
不能把构图写着可见当成真实媒体或观众验证通过。
如现有 Blocking 不足以支持镜头目标，请提出一个明确的
上游 Blocking/Beat 候选修改，不可暗改故事事实。
最终从整场 Story/Intent→Shot 和 Shot→Story 双向反查，
检查所有决定性动作/台词/知情/声音及结尾是否有充分交付。
~~~

**关键专业方法**：K5 以观众任务选镜、比较少数真正不同候选；K2 信息/声音/揭示；K6 瞬时信息、连续动作、剪点与整场时间；K4 关键 Blocking 中间态；K7 整场双向覆盖；仅当新视面或实际参考缺口出现时按 VM 参考覆盖思想识别缺项，**不强制额外三实体参考、Add Guide、FF/LF 或 Camera Tree**。**交接**：逐镜信息任务、拍法理由、对应动作/声音/状态、摄影建议、切点、观众画面证据目标、邻镜/整场约束、真实未证项。**失败**：单报“40mm/85mm”、偷换角色知情、被遮物物理露出却无可信观众窗口、无根据宣称参考已覆盖或真实可读、逐镜合理而整场遗漏。

## 4. references/review-method.md：横切专业审阅而非新审批阶段

~~~text
在任何阶段发现重大问题时，定位：
(1) 原剧本/用户确认事实冲突；
(2) 导演或时间/空间方案内部的文本可判冲突；
(3) 有合理规划但需要几何、媒体、表演或观众实证的开放项。
只对(1)/(2)指出可复核的来源与具体影响，要求修订或经授权改变上游。
对(3)说明待证条件与回看入口，不把未知改写为已通过。
提出修复候选后，检查是否真的应用，并按被修改对象复检直接后继、
相邻镜头、相关的首次观众知情时点与整场交付。
Review A 给用户确认 Intent 观众体验与重要可调整政策；
Review B 双向检查 Story/Intent→Shot 和 Shot→Story，给出有证据边界的
整场提交建议。A、B 以外除明确风险/重大选择/硬冲突不加常规人工关口。
专业 Reviewer 只能提出反例，不代表用户批准或工程 Check 通过。
~~~

**审阅契约与分工**：Creative Review 负责表达与专业选择、错误定位；WAR-35/52 工程 Check/Decision 负责结构和版本有效性，不允许 Director 自签通过。媒体层的真实可读/可听及观众理解必须保留 unknown，直到有实际对应的证据。局部 Shot 修改可检查局部与相关全场责任，但**不以局部通过宣称全场 B 已覆盖**。导演的“未证风险可有条件通过”仍受用户接受与正式 Review 逻辑约束，硬事实冲突不能豁免。

## 6. 调用层如何组合，而不把编排职责塞入 Skill

**模式是调用端决策**：Continue 可在当前会话传增量任务/新阶段卡；Refresh 必须重投 Authority、Scene Spine、活跃候选及差异；Resume 在新会话按 §12 重建这三者和精确的阶段包。源版本不一致时先阻断当前版提交、定位上游变更，不能靠 Skill “自主修复批准历史”。

**典型 Prompt 组装**（仅文字示意，不规定特定 SDK/工具）：

~~~text
固定：SKILL.md 常驻核心（只放专业立场与触发策略）
本轮：Task + Stage + Mode + 可改范围 + Authority / Scene Spine
状态：活跃候选与正式基线 diff、相关 Beat/Blocking/Shot、未证项
按需：对应 stages/xxx.md + knowledge-index 检索到的源小节
返回：Proposal / Rationale / Scope+Impact / Risk+Evidence / Next
调用端：决定候选是否有实质交接；保存时写入已批准基线与范围；
        需要 A/B 时呈交用户与现有 Review/Decision 检查。
~~~

**不要为模型运行方式创建新的剧情真相**：同一会话可同时提出多个候选，但只允许显式选择一个活跃分支；保存草案不代表批准。模型可以提出从 Shot 回 Blocking 的候选改动，调用端需再构建受影响范围与复检，不能让模型边想边覆盖正式数据。

## 7. D《错过的钥匙》：从 Shot 专业知识触发到实际决定（纸面示例）

**场景已确认的约束**：同一把银钥匙；B2 中林移开文件后在桌面 K 首次露出，观众应先于林发现；林此时没有注意，之后蓝夹重新遮挡；周只看到遮挡并推断而没有亲眼看到钥匙；后来林在再露出时发现，最后递给周**右手**。这些约束来自冻结 D 原始剧本/研究，不在本例凭空宣布用户已批准本次具体镜头方案。

**输入快照**：当前批准的 Intent（若是纸面例子，以“假设审阅 A 已通过”的虚拟基线标注）、全场 Scene Spine、B2/B3 的中间状态和邻镜、此前简化 Blender 代理在 960×540 下钥匙约 27×9px 且有遮挡的局限说明、当前工作任务“只让 Shot02 有可信观众发现机会，不让周看见、不抢林第二次发现”。真实参考素材的可读程度和镜头画面尚未验证。

**知识加载**：K1 硬故事条件简短核对；K2 观众早知/角色未见；K4 对应 Blocking 中间露出/遮挡；**K5 主导**比较保留关系镜的注意引导、调整 Blocking 露出窗口、加入客观插镜等；**K6** 核对露出时机和切点、后续遮回；K7 看 Shot03 与首次揭示关系。此例**不加载**全文 TF 工作流、VM Camera Tree、H3 参考图生成方法，亦不假设镜头改变能实证可读。

**导演应返回的有效选择示例**：
- 方案 1：保留关系镜，但将钥匙置于观众更易注意的画面信息路径，调整演员身体和文件移开后的可见时间；**前提**是不新增周的目击视角，且空间几何/画幅细节需后续验证。
- 方案 2：短暂客观的钥匙信息镜（不能标成周的 POV）交付观众早知，再切回林对钥匙的无注意状态，随后蓝夹盖住；**代价**是可能过度强调线索、割断表演流与增加镜头/编辑压力。
- 当前专业选择应该基于观众是否必须明确早知、表演连续性、戏剧悬念强弱与现有参考缺口决定；若 Blocking 不足以提供露出机会，提出**上游候选修订**，而不是导演自行改写林/周知情。
- 必须保留：“规划上可信的可见窗口 ≠ 真实视频可读/观众已理解”；旧代理像素不能直接证明成片成败。Shot03 的遮挡和周的反应及后续林第二次发现必须复检。

**失效答案**：“Shot02 用 85mm ECU 显示银钥匙，Shot03 接周看到钥匙的 POV，画面通过”——即使格式齐全，也偷换周的知情，混淆客观信息镜与人物主观视线，并把计划目标冒充媒体通过。
