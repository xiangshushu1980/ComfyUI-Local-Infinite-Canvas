# WAR-89｜Director Skill v0 文本验证与 Prompt 修订门槛（候选方法）

2026-11-14。ChatGPT 组织，供用户不逐份审阅中间产物时采用。**这是评估方案与修改规则，不是已运行的模型对照或已验收效果。**任务边界维持 WAR-89 的独立候选目录；不触碰 WAR-35/52、原 Skill、生产 Engine 或媒体；C/D/E 真正模型实验仍按上轮停点单独决定授权。

## 0. 本轮要验证什么

验证候选 Director Skill 的**专业判断**而不是 Prompt 字数、JSON 字段数、镜数或文采。四类主观察：
1. **忠实且能表达**：观众/角色首次知情、事件因果、声音时序、结尾意图的关键不变量保留；画面有可信的信息交付方式。
2. **会选而不只是会列**：针对特定观看任务比较真实替代，说明选用和放弃的导演代价；能识别镜头 POV 归因、注意力竞争及中间动作窗口。
3. **能修且不污染**：Shot→Blocking→Shot 能形成明确差异与必要复检；Resume 不混旧候选，不将例示批准当真批准。
4. **证据诚实**：文本自洽不冒充真实几何、声音、生成画面或观众理解成功。

### 专业质量锚定（不做伪精确打分）

- **有效**：相对冻结事实无冲突，有可审核、足够具体的观看/表演方案；真实不确定性有定位。
- **待修订**：方向大体合理，但关键信息的可辨/反应机会不足、错位风险未处理、替代和代价不具体；可不改上游事实而局部修。
- **阻断**：改变明确故事事实、台词、两次发现/声音因果、已确认禁项；或方案在文本中已确定无法提供必须的观看机会，却声称任务完成。
- **未证**：规划成立但需要素材、几何、动态表演、媒体或观众证据。不得因未证自动判失败，也不得将未证记成通过。

## 1. 发生问题时先归因，再决定是否修改哪一层

| 问题根因 | 直接修复对象 | 何时考虑改 Skill |
| --- | --- | --- |
| 冻结 Story Basis、批准 Intent、Scene Spine 或实际候选差异缺失/旧版本 | 调用端 Stage Packet、Authority/Resume/候选选择；阻断陈旧结果提交 | 不改 Skill 来弥补没传的事实 |
| Agent 接收到明确事实，但一次具体镜头可用其它方案修好 | 当前 Shot/Blocking 等工作候选，必要邻镜复检 | 单次创作差异通常不改 Prompt |
| 相关专业专项未加载、停止太早或检索了错误源 | references/knowledge-index.md 的触发/停止/出处，或调用端装配 | 经重现且明确是路由缺陷，才小改索引 |
| 相关知识已加载但反复缺少同类判断方法 | 精确 stages/intent / beat / blocking / shot-plan.md；真正跨阶段才考虑 SKILL.md 薄原则 | 需要跨样本或独立复现、能说明因果的证据 |
| Agent 能产生合理方案，但 Review 未识别确定冲突/错误继承 | references/review-method.md 或工程层正式 Review/Decision（不得在 WAR-89 私建） | 只改横切核查方法，不在四张卡都塞同样禁令 |
| 文本具可行构想但影像/声音/表演/观众实际效果仍未知 | 后续 Canvas/几何/媒体实验与素材管理 | 不因缺失媒体证据而把更多文本限制硬编码 |

**硬阻断例外**：一次明确侵犯冻结事实就拒绝本候选，且应立即定位来源；若输入完整、Agent 仍稳定给出同类违规，可先小修对应阶段卡/Review，再进行独立回归。不以“必须发生两次”推迟阻断，但不把单个随机失败当系统性 Prompt 缺陷。

**优先级建议**：事实硬冲突 > 明确看不到/听不到关键证据的规划缺陷 > 局部可修导演选择 > 风格多解。证据不充分时写“待验证”，不可把单次主观偏好写成新增硬约束。

## 2. 后续冻结文本测试建议（本轮不执行）

素材包已有：`director-skill-v0-ce-minimal-text-cases-20261114.md`（C/E 原文、SHA、失败判据）；D 源与纸面参考在 `director-skill-v0-d-paper-walkthrough-20261114.md`。先完成 F1/F2 的七文件小修并冻结提交，然后再决定试验批次。

- **C《没说出口》**：陈自停而非广播打断；许确实听懂；第二次广播晚于“嗯”；允许同镜/反应镜不同选择，不夸张补剧情。
- **D《错过的钥匙》**：观众先知、林第一次未注意、周只推断、再遮→再露/发现、唯一钥匙/右手；同时核镜头归因为林或周 POV 的误读风险、真实备选及 Shot→Blocking 局部返回。
- **E《最后一张照片》**：不提前泄露过去承诺的**核心语义**；翻面后林与观众同步首次读字；结尾正面朝上相册旁未收；无实际文字图片资产。

若获授权开展真实文本模型试跑，建议固定同一组冻结输入、同一模型/思考努力/调用模式、明确是否提供 A-demo、统一可改范围与相关阶段包，**分开保存**最小 Native baseline 与七文件 Candidate 结果。模型本身真实输出与评阅意见分文件；不可把期望失败判据直接混入受测导演 Prompt 造成答案泄露。C/D/E 可做小样本诊断，不以三例计算“成功率”；若比较 Continue/Resume，须控制输入版本与活跃候选，允许不同镜数和摄影方案。

## 3. Prompt 变更决策门槛

**允许变更（需留最小证据）**：
- **P0 硬冲突**：已确认权威输入确实到达且未污染，仍产生清楚违反故事因果/知情/禁项的结果；可直接退回/阻断候选。单次也可起草局部防错修订，但必须对旧错误和至少一例相邻合理解做回归，不能当成验证过的系统改善。
- **P1 系统性专业缺口**：至少两个不同案例/场景，或同一案例的独立受控重试，均缺失同一种判断，且已排除输入缺失、模型偶然和未加载知识；小改对应 stage 卡或知识索引。
- **P2 选择质量差**：镜头勉强、过度解释、趣味不足、局部节奏不佳，但没有确定来源冲突。优先让 Agent 局部解释、比较一项替代并修订。只有出现有一致方向的反复退化且可被评阅者指出证据，才考虑改 Prompt。
- **P3 风格分歧/媒介未知**：多解合理、观众真实体验未测，不改 Skill；进入后续素材/Canvas/媒体验证。

**修改护栏**：每轮只动一层（优先知识路由或一个 Stage 专项，慎动常驻 SKILL），保存旧 SHA/commit、触发失败的真实输入和输出、修改后的预期行为、负面副作用与回归结果。用原失败案例 + C/D/E 其它相关案例做回归，后续补一个未参与 Prompt 写作的保留场景防过拟合。不为了某个 C/D/E 答案把角色名字、固定时长或示例镜数写成通用硬规则。修正后若只在旧输入改善、其它故事能力下降则撤回/重做。

**面向用户的报告**：日常不展示每个阶段的整段表格，只报告本轮实质专业结论、明确失败、影响层和下一步；仅在 A/B 两默认批准关口、要改作者/已批准事实、反复高影响争点或需新模型/媒体预算授权时升级用户。模型自己给出漂亮理由不能替代验收依据。
