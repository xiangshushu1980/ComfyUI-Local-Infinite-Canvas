# WAR-89｜Director Skill v0 · C/D/E 首轮受控文本对照独立审阅

2026-11-14｜执行 Eric｜组织与评阅 ChatGPT GPT-6｜创作模型 Codex `gpt-6-astra` Medium。**性质：真实模型文本实验，不是纸面推演；不含图像、几何、动态表演、观众试映、正式批准或生产 Skill 安装。** 用户本轮授权先执行最小文本对照，除重大漏洞外只记录问题，实际交互中再迭代。

## 一、结论

**六次调用全部正常完成；首轮三个剧本未发现明确的故事硬冲突，也没有发现应立即修改候选 Skill 的系统性专业判断缺陷。**

Native 与 Director Skill v0 都能依据源故事做出具体、可审阅、具真实代价的镜头选择。候选 Skill 相对清楚地说明了部分「观众任务—调度/机位—取舍—邻镜复检—媒体未知」，但 Native 本身也较强，不能把三案例的一次性比较解读为候选 Skill 获得了可量化优势或已经优于 Native。对同一剧本采用不同镜数、机位或情绪侧重，若不改变事实和观众信息时序，应视为导演多解，而不是错误。

**处理决定：本轮不修改七文件 Prompt，不因风格差异或未生成真实画面而添加硬规则。** 所有可疑项均保留为候选拍法的后续 Canvas/交互验证条件。WAR-89 仍 In Progress，停在「文本第一轮无重大漏洞；待未来真实交互/局部修改/媒体验证」；本轮不继续大规模优化 Prompt。

### D 的专业观察与上轮纸面推演的差别

上轮 D 纸面演示选了「客观钥匙细节 Shot02＋关系 Shot03」，并提出 F1/F2 修补。本轮受控运行时，Native 和 Candidate 均自主选了**同一关系镜中完成首次显露与覆盖**，且把「客观插镜」作为可转用替代。因为源故事规定的是观众与人物的信息时序，并没有要求固定镜数/机位，两组改变拍法是可接受专业判断。它们同时承认小物件能否辨认尚未验证，因此**没有理由强迫 Candidate 复现纸面选择**。

## 四、发现、归因与修订决定

### 未出现需要当场修复的严重漏洞

没有发现 C 广播错误打断、许不理解；没有发现 D 周提前确定看见钥匙、林首次发现、钥匙多把或错误交接；没有发现 E 翻面前公开承诺含义、先让林读完后观众才看到、照片收入相册/改变搬离决定的明确文本计划。因此不执行新一轮 Prompt patch。

### 保留三项后续专业风险（记录而非立即修改）

1. **D：小钥匙与人物注意力在一镜中的竞争。** 两组都提出 1–3 秒候选辨认时间，但文本没有可靠的观众阈值。若未来生成画面中钥匙无法辨认，应优先局部替换为客观细节镜，复检林/周 POV 归因与邻镜动作，而不是把“必须插镜”写成通用 Skill 禁令。
2. **E：翻面过程中可能过早泄露部分文字的核心含义。** Native 的“字迹斜掠而过”可能风险较高，Candidate 相对谨慎；缺实际画面/字迹资产不能断言硬失败。以后应以**完整意思是否被提前读出**为准，而非只看完整句显示与否；如出现真实泄露，先修该镜头中的持片角度与切点。
3. **C：陈自主收句与许已理解是否真的能靠微表演读懂。** 两组均将声音与顺序写对，但观众可能只看出一般告别。未来先尝试局部动作与声音/镜头审阅，不增解释性对白或关系背景。

### 与 Skill 修改门槛的对应

- P0 事实硬冲突：本轮未检出。 
- P1 需跨样本/重试的稳定专业判断缺口：本轮未检出。
- P2 局部可修的拍法风险：上述三项，**记录供 Canvas 交互**。
- P3 未证媒体/观众效果：存在，是未来阶段应验证的对象而非 Prompt 失败。

**当前 Skill 七文件无需改动，也无充分证据宣称比 Native 全面更好。** 专业知识路由是否只加载真正需要的章节，B-flex 断点恢复是否有效，需在后续真实调用/用户交互中另行验证。本轮只证明「能读 Skill 并产出至少三种没有明显故事冲突的文本导演候选」，不证明生产闭环或影像成功。
