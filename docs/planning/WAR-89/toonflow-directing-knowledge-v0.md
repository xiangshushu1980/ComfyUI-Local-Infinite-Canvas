## 2. Agent 应学习的判断方法

以下逐条给出**创作问题、方法、阶段与来源**。所有条目均为“已阅读 / 候选提取”，不是“已实现 / 已测试有效”。

| ID | 专业判断与触发情境 | Agent 可用的最小操作方法（重新表述） | 建议调用层 | 冻结来源与风险 |
| --- | --- | --- | --- | --- |
| TF-01 | 如何理解一场戏为什么值得拍 | 识别人物想达到的目标、阻碍与选择，分清可见事件、潜台词及观众尚不知情的信息；只对已确认材料提出解释。 | Intent | `knowledge/scriptCraft.md §故事核、矛盾与结构／人物小传`；不把剧本改写方法当作既有事实。 |
| TF-02 | 怎样设计信息差、悬念与揭示 | 同时考虑“事实是什么、各角色知道什么、观众知道/误以为什么、何时揭露”；误导必须由真实可回看的线索成立。 | Intent→Beat | `knowledge/scriptCraft.md §信息差、钩子与反转`；故事改写需获许可。 |
| TF-03 | 如何选择情绪推进而非堆戏 | 为段落描述起点、压力变化、转折与释放；类型方法用于解释叙事，不应按固定秒点制造高潮。 | Intent→Beat | `knowledge/scriptCraft.md §单集情绪、动作与台词`、`knowledge/narrativeGenres.md`；不是固定结构。 |
| TF-04 | 哪些情绪需要表演落实 | 把“压抑、迟疑、决意”改写为有剧本依据的呼吸、视线、姿态、动作速度、短停顿；没有依据时提出候选，不擅自加摔物/哭戏。 | Blocking | `knowledge/shotCraft.md §分场与表演依据`。 |
| TF-05 | 一个新镜头为什么存在 | 先陈述它给观众的**新增信息或注意力变化**，再选择景别、视点、构图；仅同画面的微反应或连续对白，不因动作发生就必切镜。 | Shot Plan | `knowledge/shotCraft.md §镜头语法`，WAR-57；启发式非自动评分。 |
| TF-06 | 如何决定何时切镜或留长镜 | 切换时空、观众关注主体、关键动作节点或有意义的视觉关系时可以切；若一个稳定画面可连续传递信息，应考虑长镜，避免信息零增量的镜头堆叠。 | Beat↔Shot Plan | `knowledge/shotCraft.md §镜头语法`；“镜少=好”同样错误。 |
| TF-07 | 景别服务哪种表达 | 用远景交代空间/距离，中景承载互动，近景承载反应，特写强调关键细节；裁切及可见对象要明确，术语本身不能替代构图。 | Shot Plan | `knowledge/shotCraft.md §景别与信息用途`；景别选择不是固定处方。 |
| TF-08 | 角度、视点、运镜的选择依据 | 先确定“谁从哪里看什么、观众为何要这样看”；机位角度与运镜区分；移动镜头需有起幅、路径、新增信息及落幅，允许固定镜。 | Shot Plan | `knowledge/shotCraft.md §角度、视点与运镜`；模型能力需另核。 |
| TF-09 | 两人/多人关系如何保持空间可读 | 建立相对左右、前后、互动轴、朝向、眼线和物件位置；反打维持可理解方向；走位或跨轴须有可见建立过程。 | Blocking→Shot/Review | `knowledge/shotCraft.md §空间与连续性`；九格是可选工作记法，不复制原 Canvas 字段。 |
| TF-10 | 相邻镜之间什么必须承接 | 检查人物在场位置、持物手、道具归属、动作进度、衣物/场景状态、眼线；动作没完成不能凭切镜宣称终态。 | Blocking / Review | `knowledge/shotCraft.md §空间与连续性`；文字一致不等于几何与媒体成立。 |
| TF-11 | 表现信息应否依赖看得见的证据 | 关键事实应有明确可见/可听呈现条件；角色知道与观众能看见不能混同；仅写“揭示线索”不等于镜头确实可读。 | Intent→Shot / Review | `knowledge/shotCraft.md §审阅方法` + WAR-61 D/E；需要后续媒体审阅。 |
| TF-12 | 长台词与动作的时间安排 | 按文本、实际语言速度、自然停顿及收放余量粗排；连续台词可用听者反应/跨镜声音承接；不可为了时长删原词、重复对白或凭空补动作。 | Beat / Shot | `knowledge/shotCraft.md §台词与时长`、`storyboardTable.md §拆分方法`；2/3/4 字每秒、20字阈值皆源启发式。 |
| TF-13 | 片段边界的动作/声音连接 | 说明前段预计终态与本段起态，用动作、视线、情绪或声源作为桥梁；是否硬切/过场由叙事决定，而非每场必有转场。 | Blocking↔Shot | `knowledge/shotCraft.md §空间与连续性`、`storyboardTable.md`。 |

## 4. 怎样让 Agent 真正使用，而不是朗读规则

**建议知识调用方式，不是 API 设计：**
1. Intent 问：本场核心冲突是什么？观众与人物的知情差应如何变化？欲得到何种情绪或视觉体验？如需类型判断，按选定类型加载 TF-15。
2. Beat 问：每次有意义的知情、目标、关系或情绪变化是什么？哪些变化需要被观众看见？不规定 Beat = Shot。
3. Blocking 问：人物怎样以视线、停顿、动作和相对空间表现这种变化？有哪些物件和知情状态必须连续？
4. Shot Plan 问：每镜增加或延迟了什么信息？有没有无需切镜的方案？选景别、机位与切点的专业理由是什么？可能损失什么？
5. Review 问：哪些只是模型提出的候选、哪些是确证来源、哪些依赖画面可读性或实际视频才可判断？指出具体场景/镜头与可选修法。

**示意演练（方法演示，非已生成结果）：**在 D《错过的钥匙》中，导演希望“观众先看到钥匙，角色暂时没注意到”。可先比较两种镜头方法：（A）保持人物关系镜，通过调度和注意力导向让钥匙进入画面；（B）插入钥匙特写明确交代线索。Agent 应说明 A 的好处是维持情绪连续、风险是钥匙可能太小或被挡；B 的好处是线索较明确、代价是提前显露视点和可能打断表演。若文字方案没有证明可见像素、遮挡与时长，则应记为未证，不能由 Engineering 自动改焦距来“修复创意”。关联的真实冻结观察见 WAR-61 D 与 WAR-72，而**这个对比示例是本次提取中的说明性推演**。
