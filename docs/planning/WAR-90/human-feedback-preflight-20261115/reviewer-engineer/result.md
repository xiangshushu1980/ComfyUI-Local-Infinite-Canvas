**P0｜进入执行前的阻塞项**
- 隔离不能仅凭“临时 HOME＋专用 profile”成立。旧联调证明当次隔离项目操作及清理成功，不能证明新会话连接正确；反例是原 smoke 因生产浏览器仍连接而拒绝。首次写入前须核对独立端口、进程、profile、客户端及 MCP 实际路由，读回预期 projectId；目标不明、多客户端或生产连接混入即停，退回 Chat。
- `capture_feedback` 只验节点标题、ID及含 Shot/B 标签的截断内容，不能证明显示全文等于批准文本。反例：保留标签、改写后半段仍可通过。Canvas 路径须取得完整正文核验，或以可核验的 Chat 冻结全文为阅读权威，并明确画布全文未验证；不得宣称已经验证显示版本一致。
- `external-user-unverified` 是来源标记，不是真人证明。保留实际用户消息及其上下文、原文 SHA；模型建议和画布文字均不得升级为用户指令或批准。无真实意见即停。

**P1｜最小技术与证据补齐**
①工程可证：冻结报告记载 prepare/submit 的54项测试通过、过期及重复提交拒绝、Runtime 不调用模型；真实联调仅得到 `no-handoff`。这不能证明修改闭环成功。prepare 后至 submit 前应重验权威版本、目标与反馈绑定；状态改变则作废旧 run，不自动重试或调用第二个模型。将反馈 envelope SHA 纳入运行证据；`validate_feedback` 补验 origin 白名单及身份未验证标记，将原文限定为待处理数据，不能覆盖范围和审批规则。
