## WAR-90 真人反馈采集预检审阅

**结论：targeted-revision；真人采集仍未执行。** 当前没有用户新意见，也没有生产 Canvas/媒体授权。报告只能审阅测试方案，不能把专业推断写成真人反馈或实测结果。

**P0｜先改给人的材料，避免把答案塞进题目。** 冻结 B 的 Shot02 是高度规定性的导演说明，直接附上会让读者看到“首次露钥匙、蓝夹再遮、整理持续”等预期答案；方案又把这整条序列写进“面向人的测试目的”。这不足以证明普通审阅者能自行指出局部表达问题。冻结材料也明确提醒：“失败判据与受测生成模型的输入隔离”，同一原则应适用于真人提问：提供 Shot02 的批准原文及理解上下文所需的相邻镜头，但题干只问“你最希望改进这一镜的哪一点？请指出具体位置和希望达到的效果”，不列预设缺陷、修法或剧情答案。可附中性选项“暂时没有修改意见”。不要把事实核对题伪装成开放反馈。**待实测**的是读者能否实际提出可定位的局部意见；冻结证据不能证明可读性或代表性。

**P1｜清楚标明反馈入口和身份边界。** 方案第2步称通过“Chat 提供明确的实际修改意见”，第1、5步又讨论隔离 Canvas 与“正式反馈输入点”，容易让人混淆输入究竟来自 Chat 还是 Canvas UI。每条原文应记录入口（Chat／测试 Canvas UI）、目标 Shot、时间/轮次，以及 `external-user-unverified`；注明身份未验证、不是 B 批准。不得把导演建议或提示内容当用户意见。已有 `capture_feedback` 能校验画布项目、选区和绑定版本，但明确 `actor_identity_verified=False`；它**不能证明**反馈是用户输入，也不能覆盖 Chat 入口的来源记录。若从 Chat 收集，就如实标 Chat 来源，不能宣称已验证 Canvas UI 真人输入。未经人主动写出的意见不得补造。

**P1｜无用户回复时，在收集关口停止。** 可以继续做的是准备中性审阅材料、说明正式输入入口和边界，以及复核冻结版本信息；可以报告目标材料是否准备好、尚未发生真人输入。没有回复，就不能执行 `capture_feedback`、克隆修订工作区或启动导演修订，也不能报告局部修改、差异回显、邻镜复核或新 B 审阅已经验证。现有联调只证明单 Agent 对已批准 B 的只读诊断可达 `no-handoff`；它没有验证真人输入或修改型候选。方案写明“无真人意见就停”，应作为执行硬门槛。

**P2｜正式 UI 范围与最小执行顺序。** WAR-37 才负责正式 UI；本轮不得借真人预检扩展生产 UI、Canvas 服务或新 HTTP bridge。冻结方案允许已有隔离 Agent、持久浏览器 profile 和 Canvas MCP；若不能可靠隔离，应退回 Chat 采集，并明确“未完成 Canvas UI 真人输入”。现有 `feedback_bridge.py` 是 pilot transport，不是身份验证或 WAR-35 契约；其目录校验不能代替人工确认输入来源。

**最小方案：**先制作不带预设答案的 Shot02 审阅材料，并标明 Chat 或隔离测试 Canvas 的实际反馈入口；等待真人给出具体意见；记录原文和入口并标为未验证身份；只有收到意见后，才按冻结 B/Source/Shot 版本绑定，进入隔离修订与复核流程，并停在真人 B 审阅。若无人回复，报告“材料已准备，真人输入未发生”，到此结束。
