## 2. 四层一致性：工程约束与导演判断各自到哪里为止

| 层 | 由谁拥有权威与输出 | 可以确定性/程序化核查什么 | 不得假装已证明 |
| --- | --- | --- | --- |
| **W：世界与故事状态** | Story Basis/批准 Intent + Beat/Action/StateDelta（当前 WAR-35 语义，Engine 未来实现） | 单个 K、位置/归属变化、手部持物、动作完成只发生一次、对白与角色知情状态顺序；Shot 边界/共享 Action 引用合法，版本依赖未过期 | “知情状态已写好”不意味着角色眼睛实际能看到 |
| **B：调度与可观察条件** | **Director Agent 在 Blocking 提方案**：角色路线、动作起止、中间态、观察通道、姿态替代和保留的风险 | 依据已有确定事实检查互相矛盾的要求；对触发风险的镜头构造**几何检查请求**，交 CPU Blender/其它经过验证的工具核对距离、遮挡、接触及有限姿态 | 某个低模姿态失败＝故事/导演方案必然不可拍；摄像机能看到＝演员注意/知晓 |
| **S：摄影与观众观看任务** | **Director Agent 在 Shot Plan 选机位/切点**，说明相对视角、需可见目标、行动/信息时间窗及邻镜对齐 | 已有场景与机位资产时，Camera Projection/Raycast 返回可测投影大小、遮挡样本、轴侧、邻镜切点对应状态；将结果作为 Review evidence | 9/9 射线畅通、像素达到某宽度＝真实观众认出；“客观”文字标签＝观众不会误读成 POV |
| **R：视觉参考依赖** | **制作／参考规划器（未来按需）**：新机位所需图像、旧参考覆盖与缺失视面；可借鉴 ViMax Camera Tree 的 parent camera/shot 与 missing_info | 父节点/Shot 引用与无环等**结构校验**；有真实图片时，另做图像覆盖/外观一致性检查 | Camera Tree 自己计算世界 XYZ、证明机位/物体真实空间关系、管理不同时间的持物变化 |

共同原则：**世界坐标≠画面左右；几何可见≠人物注意≠观众辨认；物理证明与真人观看分层**。参考图树只在生成多视角/分镜素材且确实存在参考资产时介入，不是 v0 文本 Shot 审阅的前置门槛。

## 3. 最小调用闭环（设计接口，不等于现有 API 已实现）

`用户批准 Story/Intent + 当前活动候选 + 真实问题` → **Director Agent** 输出选定 Blocking/Shot 要求与候选替代及可见判据 → **轻量调用端** 将当前受影响 Action/StateDelta/Blocking/Shot + 已确认世界锚点/机位/旧有效证据，组装**局部 Check Request** → **已有工程/Blender CPU** 对能够计算的条件返回命中、遮挡、可达、样本与限制 → **Review** 绑定候选 revision/source hash/evidence，区分 `text conflict / proxy fail / unknown / actual media` → **Director Agent** 基于具体反例调整 *候选* Blocking/Shot → 局部状态与邻镜复检 → 如属重大实质变更交真实用户 B 重新审阅。

最小 Check Request 仅是语义调用视图，**不新增 WAR-35 正式 Schema 字段**：
1. `target`：当前候选 revision、Blocking/Shot/Action/StateDelta 引用及时间相位（例如“蓝夹遮住 K 以后、周提问以前”）。
2. `requirement`：叙事必须成立的可反驳条件（谁从哪里看什么、物件是否触碰、交付是否可达），对应真实世界锚点；不把“观众必然理解”传给 raycast。
3. `method`：文本事实/结构规则，或指定模型、相机、姿态、时间采样的几何代理；记录工具和来源版。
4. `evidence`：实际测量结果、覆盖范围、失败/未知、输入/输出 SHA、是否仍适用于候选；**不能**把旧源代理结果挂到新派生候选上伪装通过。
5. `return_target`：先返回哪段 Blocking/Shot 和哪两侧邻镜；若用户故事或批准 Intent 硬事实需变，必须显式上行，不让检查器自动更改。

按需触发规则：普通文本同场机位无需 Blender；涉及遮挡、首次显露、细小关键道具、单次交接/手臂可达时，若视觉结果确实依赖几何才启动有限代理。无真实素材则参考图层保持 `not_applicable/unknown`；不创建假的 Camera Tree。

## 4. 将 WAR-91 反例转换成两条明确的 Blocking 修改请求

### D-BL-OBS｜周何时能看见盖住钥匙的区域

- **冻结要求**：第一次 K 露出时，摄影视线可以看到 K，林与周均尚未认出；文件夹重新盖住 K 后，周在发问前必须有可观察**覆盖区域**的通道，仍不意味着周见过 K。
- **旧代理反例**：旧人物姿态下，周移动路线的五处位置、双眼各 25 个文件夹顶面采样点**0/25 可见**；旧身位能遮住 K，也把整个采样覆盖区域挡住。此为旧 proxy 的局部失败，非新四镜 B 的必然失败。
- **候选调度 A（首选纸面建议，不是已验证修复）**：维持林在钥匙首次显露阶段的身体遮挡；蓝夹落稳、林撤回左手后，林**自然回到整理姿态并让出周看到文件夹/桌面覆盖区的角度**，而非让出 K 的首次露出时点。周接近终点与问句时刻匹配新的开放通道；不增加刻意等待或“发现 K”的新演员动作。注意：Shot02 切点要求林已经松开蓝夹，Shot03 入镜不能再演一次放夹。
- **备选 B（条件未定）**：维持林的自然姿态，调整周最后一步的到桌侧向位置或目光/头部朝向；仍不得让她在首次露出时取得 K 直视通道。不能仅在 Shot03 调个摄像机角度假装周真的看见了桌面。
- **核验条件**：T1“周两眼→K 的直接通道被合适的实际物件/人物挡住 + 摄影机→K 的必要样本无遮挡”；T2“周至少某个真实瞄向覆盖区的视面点具可见通道 + K 仍被蓝夹遮住”；必要时检碰撞和切点动作；**角色是否注意/观众是否读懂仍待表演/观看**。

### D-BL-REACH｜林右手取 K 并一次交周右手

- **冻结要求**：Shot03 尾林左手持夹、右手空、K 留桌；Shot04 才用右手实际取 K，交周右手一次完成，周随后去门，林留桌。不得移动 K、偷偷改用左手、增第二次递物。
- **旧代理反例**：旧林右肩静态锚点至 K 为 **0.88681 m**，简化两段手臂总长 **0.770 m**，差约 **0.117 m**；右前臂穿桌的旧模型失败还未消失。该旧单姿态不可达，不代表自然俯身/侧身、脚步微调后仍不可达。
- **候选调度 A（纸面建议）**：林在 Shot03 移夹、确认 K 之后至 Shot04 起取期间允许自然前倾或向桌侧移位，让**右肩至 K 的指定取物起始姿态**满足臂长/桌边接触约束；左手继续持夹避开右手与周接物路线。顺序不提前搬到林发现前。若动作必须跨 Shot03→04，应保留同一动作相位连续，不因切镜重复俯身/伸手。
- **核验条件**：取物前 K 原位、右肩/手掌实际可达且无桌面穿模；右手取起并握稳→同一 K 到双方右手短暂共同接触→周右手最终持有、林右手空；接物时左右手和人物不相交。完整人体手指/真实表演没有资产时明确未证，不能把单个肩距缩短冒充“交接通过”。

**最小纸面验收（本轮设计校验，而非实际几何复测）**：
- T-01：若改摄影机而周的眼睛仍被林挡住覆盖区域，**G2 失败不能消除**；应回 Blocking 而不是仅改 Shot。
- T-02：若让周在 K 第一次露出时先侧步到能看见 K，**违反先知策略**；该“修复”不合格。
- T-03：若林在 Shot03 末已经取 K，而 Shot04 再取一次，**重复 Action/StateDelta**；不允许。
- T-04：若新肩距已可达却无手部碰撞/握持证据，只能说“有限距离条件改善”，**不能**宣称一次交付已通过。
- T-05：若未来 Camera Tree 给出 `is_parent_fully_covers_child=true`，却没有真实图片证据，不能据此宣称钥匙投影、人物遮挡或空间连续性合格。
