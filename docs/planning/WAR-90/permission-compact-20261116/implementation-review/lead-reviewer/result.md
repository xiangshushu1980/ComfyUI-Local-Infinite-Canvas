### 上线与权限门槛

此前主审对 A3 的裁定继续有效：**“现有 `codex_approval` 必能拒绝 MCP 调用”的测试假设为 block。** 此前记录的客户端接线只覆盖三类审批请求，elicitation 自动 accept 又不等于工具执行授权；本轮没有新增证据推翻该结论。

配置探针只证明继承环境与空 `CODEX_HOME` 的配置来源差异，**不证明真实线程的工具集合、隔离效果或拒绝能力**。同样，Runtime 输出 `write_canvas: false` 是此投影的能力声明，不会撤销 Agent 通过其他工具执行写操作的权限。

正式启用前，**必须**完成：

- 两入口共同运行说明和最小权限矩阵，明确实际执行身份、工具范围、画布归属核对及审批责任。
- 正式安装所需七文件 SHA、相对路径、更新与回退检查；确认新会话实际加载版本和工具集合。
- 核实当前通路是否存在可用的 MCP 拒绝机制。若存在，证据须关联具体调用、decline 终态和工具入口未执行，并覆盖取消后的迟到调用及状态恢复。若不存在，明确报告“当前通路无法证明拒绝”，不能据此通过权限验收。
- 经授权进入集成验收时，完成原生 compact 复测；不得将既有 `review-pack` smoke 当作新增命令已测。

这些门槛**不阻断离线只读投影的针对性修订**，也不授权扩建审批系统、安装生产 Skill 或操作用户画布。

**可选：** 目标行范围、描述性哈希规则、独立允许分支以校验观测链。真实 CLI 前后业务文件核对，仅在需要宣称“实际 CLI 已验证无变化”时补做。

**延期：** 完整关联分析、正式 Schema/UI、跨入口锁与 CAS、媒体及几何验证。真实修订→邻镜复检→Canvas 差异→人类再次批准 B，等待真实用户需求和明确授权；延期不等于这些能力已通过。身份核验和正式 WAR-35 批准也继续保持未验收。

Chat 路径必须保留在共同运行说明和后续验收范围内；其 API 权限与 Canvas 原生审批链应分别核验，不能互相替代，也不能强制经独立 Codex 中转。
