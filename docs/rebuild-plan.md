## Phase 1 — 核心链路审查（只读）
- 逐层追踪画布节点/生成服务 → Gateway 接口 → Registry/Bindings → Runner/Tasks → ComfyUI → 输出收集 → 画布存储。
- 研究 Canvas Agent / MCP / 状态与画布操作，优先复用，不另建 Agent 编排架构。
- 给每个拟剥离模块登记直接调用者、间接影响、配置与测试覆盖。
- 退出条件：形成可复核的模块依赖图，候选功能有具体保留理由。

## Phase 2 — 参考系统验证（另行授权）
- 优先静态 typecheck、已有单测；再考虑 Mock 与本机真实环境。
- 在不修改既有 ComfyUI 的前提下检查接口、资源、任务状态与输出回写。
- 每项验证填入 `validation-matrix.md`，区分静态检查、测试与真机验证。
- 退出条件：核心路径可用或问题被明确定位；未验证项不写“完成”。

## Phase 3 — 最小可回滚精简（逐依赖簇实施）
- 先关闭不需要的入口/业务，保留底层通用模块；再根据依赖图决定删除。
- 用户已决定并授权从当前版本剥离源码修复助手；2026-11-03 已清理其源码、前端、Gateway、启动器和补丁包入口，生产 dist 构建与回归待执行。更新/发布业务和非创作类 UI 仍需分别评估，不预先承诺删除。
- 每次只变更一个依赖簇，运行关联测试与功能回归；保留回退 commit。
- 退出条件：画布、Gateway、ComfyUI 核心功能不退化。

## Phase 4 — 本地环境及创作工作流适配（另行授权）
- 对齐本机连接方式，按需处理 Launcher 跨平台与模型/节点发现逻辑。
- 以注册与绑定方式逐项接入 Qwen Image、H3、视频处理、3D；避免单工作流硬编码。
- 每条工作流分别验证参数变化、任务取消、结果回写与持久化。
- 退出条件：至少一个端到端创作工作流可重复运行并有记录。

## Phase 5 — Agent 创作操作
- 复用原生 Canvas Agent 的读取、选择、操作能力，验证授权与用户确认。
- 再设计 Agent 调用工作流、监控任务与组织媒体资产的最小扩展。
- 退出条件：操作有边界、可追踪、可回滚，无重复代理系统。

## 变更控制
- 不默认重写，不以“目录复杂”为删除理由。
- 每个代码 PR/commit 附：目标、影响范围、依赖查询、验证结果、回滚方案。
- 未授权前只修改项目文档；不装包、不启停服务、不执行 GPU 工作流。
