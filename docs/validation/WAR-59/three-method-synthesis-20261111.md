# WAR-59｜Toonflow、DirectorSKILL、ViMax 综合研究（2026-11-11）

状态：完成既有文本/源码证据的跨 Skill 综合评审；非新实验，不构成视频或几何可行性验收。任务入口：[WAR-59](https://linear.app/xiangshushu/issue/WAR-59)。相关研究：[WAR-61](../WAR-61/cde-cross-sample-review-20261111.md)、[WAR-65](../WAR-65/cde-cross-sample-review-20261111.md)、[WAR-66](../WAR-66/README.md)。

## 1. 结论摘要

三方法不是功能完全同构的三套“导演替代品”。**Toonflow** 重视解释剧情、表达情绪及信息揭示，并将 Director Plan 交给 Storyboard；**DirectorSKILL** 重视戏剧 Beat、导演整体政策、Blocking/Shot Plan 和规则化风险发现；**ViMax** 更偏向已确定镜头的首帧（FF）—运动（Motion）—尾帧（LF）描述，以及以 Camera Tree 安排跨机位参考的来源与缺失细节。机制可以顺序借鉴，但还没有证明相互自动调用更优，也不能把任一 Camera Tree 当作真实空间或跨镜叙事连续性检查器。

## 3. 直接证据与边界

**Toonflow（WAR-61）**：C 12 Shot/36s，保留未尽之言和告别；D 13 Shot/40s，钥匙的显露—遮挡—重现与右手交接均有镜头功能；E 15 Shot/42s，翻面—文字首次揭示—反应有明确顺序。三例为 Terra Medium 对原规则的文本回放，非完整 App，未实测媒体或空间几何。其强项是从戏剧表达延伸到镜头意图，不能以较多 Shot 直接断言更好。

**DirectorSKILL（WAR-65）**：C 5 Beat→7 Shot/32s，能因“过年的时候……”的停顿增加人物反应；D 6 Beat→8 Shot/38s，对唯一钥匙与右手交接有状态跟踪，Shot08 交接 Red；E 6 Beat→6 Shot/40s，追踪文字首次可读与照片正反/位置，Shot02 入册 Red。D Shot07→08 与 E Shot05→06 的剪辑跳切/角度风险已被文本指出但未回写和复检；D/E 部分几何、动作约束未证明。规则化风险发现**不等于**风险已被解决；六维风险色也不等于 H3 成功概率。

**ViMax（WAR-66）**：源码与 C 三镜研究者编写 ShotBrief 的 Prompt 回放（集中和独立），均非完整 Python/图像链。FF/Motion/LF 能保留局部人物与票据状态；Camera Tree 生成 Camera0 根、Camera1 以 Camera0 的 Shot0 为父，并文本判断父参考缺脸部/手部细节，但不做 3D 视线验证。独立 Shot0 增加未授权离场而 LF 未更新，Shot1/2 有首帧与 Motion 重复；集中 vs 独立的 Schema/请求组织、随机性未被严格控制，不能得出普遍优劣结论。

三者样本、输入资产和执行适配不同，**不做性能质量排名**；冻结源码、输入、输出、模型、日志和 SHA 均以各子任务的索引为准。历史 P0–P2、E2/E3 视频在 WAR-59 原任务保留，不拿它们进行未控制的跨方法排名。

## 4. 共性断点与检查设计

1. **故事表达正确不保证导演选择最佳**：应在导演意图层明确观众此刻知道什么、感受什么，谁在施压与回避；各镜头需指出其叙事功能及替代方案。
2. **导演规划正确不保证场面调度可拍**：例如 D 要求摄影机看到 K、人物在移动时看不到 K，E 要求角色和观众同时读到翻面的文字；没有 2D/3D 位置与遮挡验证就不能宣称几何成立。
3. **风险提示不等于闭环**：生成镜头候选→逐镜/镜间检查→提出修正→实际回写候选→复检所有约束→冻结；WAR-65 的 Red 和剪辑风险停在提示/建议阶段。
4. **镜内首尾与跨镜状态是两层**：ViMax 的 Motion/LF 需要自洽，跨镜仍需独立状态账本（谁持物、朝向、位置、知情、发生了什么），且 Camera Tree 的视觉参考依赖不等于状态迁移。
5. **视频遵循另需实测**：导演方案的几何可行、H3 对镜头/表演/对白的遵循及最终剪辑观感彼此不可替代。当前无授权媒体生产；历史 E2/E3 的参考图混杂和 E3 未完成人工 QC 不可忽略。

## 5. 对 Canvas Lab 的阶段职责建议（研究假设，未批准实现）

`剧本/原著 → 戏剧理解（人物欲望、潜台词、信息揭示） → 导演意图（观众应看到/感受什么） → Beat/表演与 Blocking（位置、道具、状态转折） → Shot Plan（为何这样拍与这样切） → 连续性与可执行检查（逐镜+镜间；必要时几何预演） → 镜内 FF/Motion/LF 与机位参考组织（需要素材/关键帧时） → H3 提示词和生成 → 人工视听 QC`。

这不是简单顺次调用三个原 Skill 的已验证管线。同一意图/Blocking 若在两个 Skill 内被重新独立生成，可能出现镜数、动作或信息揭示矛盾；实际复用应定义每阶段唯一权威状态、输入输出契约、阶段审阅及失败回退。尤其 **当前 H3 Ref2VA 直出** 以实体 reference + 多 Beat Prompt 为主，ViMax 图像链/Camera Tree 不是必经步骤；未来引入独立关键帧、分镜图或多机位图像时才更直接相关。不可把 FF/LF 当作已获许可的 Add Guide。

## 6. 下一研究决策与验收分界

现有研究已足以完成 WAR-61、WAR-65 的**原版文本观察研究范围**，WAR-66 已完成缩减研究。WAR-59 本轮综合机制评审亦完成，但父任务可能继续用于下一阶段路线决策；是否关闭父任务与是否立新任务取决于该决策，不自动展开新的 Skill 改写或视频实验。

后续最有信息量的单一方向是 **同一剧本的逐阶段交互式导演审阅**：首先讨论剧本表达和观众信息/情绪目标，然后审阅并必要时迭代导演政策、表演/Blocking、Shot Plan 与连续性检查，并记录每次反馈前后差异。这是新研究范围，必须与历史单轮原版只读回放分开。若后续引入 2D/Blender 几何、静态分镜或 H3，逐项确定验收与授权；优先解决未闭环的状态/空间/剪辑约束，而非追求镜数或几秒误差。
