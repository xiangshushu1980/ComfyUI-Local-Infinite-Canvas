# WAR-66｜C 三镜独立调用 vs 集中调用对照（2026-11-11）

## 问题与实验方法

要区分：单镜头拆解是否主要依赖镜头描述本身的充分性/专业性，或依赖同一次模型调用中可见的其他镜头。此次只控制**调用组织形式**，没有操纵单镜头描述专业度，因此是对“多镜上下文是否必要”的初步观察，**不能据此完成二者因果归因或质量排序**。

- 共同输入：已冻结 C 剧本导出的三个**研究者编写**的镜头候选 Shot 0/1/2，来源 `../minimal-C-text-v1/fixture-shots.json`；原始 ViMax SYSTEM/HUMAN Prompt 文本来自 `../minimal-C-text-v1/decomposition-messages.json`，内容未改变。
- 旧实验（集中）：`../minimal-C-text-v1/decomposition-raw.txt`，3 组 SYSTEM/HUMAN 依次装入一次 Codex CLI 请求，统一 3 镜 JSON Schema。
- 本次（分开）：本目录 `shot-0`、`shot-1`、`shot-2` 每个独立启动 Codex CLI，独立工作目录、独立短期会话，每次只传入一组 SYSTEM/HUMAN Prompt，单镜头 JSON Schema。模型固定 Eric Codex CLI 0.166.0 / `gpt-6.1-terra` / medium / read-only / ephemeral / ignore-user-config / ignore-rules。
- 两组共有的执行适配：Codex SYSTEM/HUMAN 文本包装、JSON Schema 替代 LangChain PydanticOutputParser.format_instructions；不是 ViMax Python Pipeline 正式实跑。两组没有保持**完全相同**的 JSON schema 包装/请求指令（集中为数组，独立为单对象），也没固定生成随机种子；是初步对照，而不是充分控制的因果试验。
- 三个独立调用均返回结构化 JSON，退出码 0，原始 `request.txt`、`response.json`、`execution.json`、`events.jsonl`、`stderr.txt` 及 SHA 均保存在 `shot-N/`；总清单 `sha256-manifest.json`。未生成图像/视频。
  
## 逐镜对照（事实与推断分开）

| 镜头 | 集中输出 | 独立输出 | 判断 |
| --- | --- | --- | --- |
| Shot 0 双人开场 | 仅叮嘱和答“好”，尾帧两人未离场 | Motion **新增“随后，她转身走向检票口”**，而原镜头输入没有；LF 仍保留许在右侧站立 | **观察到明确越界 + Motion/LF 未闭环**。独立调用未必比集中调用忠实；不能由单次差异断言集中模式有普遍优势 |
| Shot 1 看票欲言又止 | FF 没预写低头；Motion 包含低头→抬头→说话停住；LF 持票 | FF 已写“低头看票”，Motion 又写“先低头看票”；同时额外推断许不入镜、闭嘴尾态 | **动作起点与 Motion 有轻微重复/时序不清**；停顿与持票仍保留。独立 Motion 中用了「许」指名，不完全符合原 Prompt 的 motion 禁用直接姓名要求 |
| Shot 2 许离场 | FF 两人面向检票口→Motion 许转向陈→离场，LF 远离 | FF 把许已经朝向陈、陈也面向许；Motion 仍说许“转头看陈”，形成动作重复 | **预先完成动作，FF→Motion 起点矛盾**；核心离场及票仍保留 |

其他共同点：两组均返回三个镜头的 `variation_type=small`，三个镜头角色索引分别为 `[0,1]`、`[0]`、`[0,1]`；两组都保留陈的车票、许的包和离场距离变化。特别是 Shot 2 在宽景中人物大幅远离仍被标记 small，提示该类型更关注单镜构图/运动程度，不直接量化叙事状态变化。

## 回答用户提出的分野

1. **输入描述自身已有足够多的剧情/道具状态事实**：例如每一镜都单独注明“陈持票”，末镜明确“许离场”，所以“独立模式也能保持这些事实”不证明它具备跨镜连续性推理，恰恰符合单镜详细描述足以传递局部约束。
2. **此次独立模式反而发生状态幻觉与时序错误**：最明显是开场 Shot 0 擅自提前让许走向检票口；其 Motion 没有在 LF 中完整体现。假设在集中模式共享后续镜头信息可帮助抑制此类越界，但这只是待检假设，不能凭一次运行证明。
3. **复杂度与专业化仍重要**：原本三镜由研究者先设计，包含景别、人物左右、朝向、道具、镜头运动与终态；它们本身已解决了大量传统 Shot Plan/Blocking 的工作。此对照没有提供“模糊单镜 Prompt vs 充分专业单镜 Prompt”的受控条件，故不能说分开调用更好/更差来自专业程度。
4. **真正可验证的研究问题**：未来如需进一步分辨变量，可以选同一镜头的“只交代剧情”与“明确 Blocking/起止状态”的两个版本，并分别在独立与聚合上下文中多轮重复，形成 2×2 条件矩阵；控制内容而不是把跨镜信息和 Prompt 精度混为一谈。目前不自动扩大实验。
5. **对 Canvas Lab**：与其假设 LLM 自动从多镜上下文“记住”全部状态，更稳妥的是由上游 Shot Plan/Blocking 明确提供每镜的视觉输入状态、目标动作、最终状态，再检查 FF/Motion/LF 是否满足输入与自身一致性；Camera Tree 仍仅管理视觉机位参考，不负责这些时间状态闭环。

## 研究限制及结论等级

- **已观察**：独立模式 3/3 结构化输出成功；Shot 0 明确越界；Shot 1/2 有首帧动作重复；两组基本道具与结果稳定。
- **不能证明**：集中调用优于独立调用，或单镜专业描述比共享上下文影响更大。这需要多个随机重复和 2×2 设计。集中调用拥有跨镜可见上下文、调用框架不同，也不能当原版 ViMax 模型行为的严格对照。
- 本次测试完成后原集中记录及 Camera Tree 保持不变；ViMax 图像参考和 H3 依然未测。**本结果支持单镜精确输入加终态验证的重要性，而不是宣称已证实其绝对优势。**
