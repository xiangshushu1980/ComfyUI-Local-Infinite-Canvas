# WAR-68 · 导演决策链深度研究计划（最终 Skill 设计前置）

> 2026-11-12。**任务已经创建，机制实验尚未开始。** Eric 项目根目录 `/home/sean/projects/canvas-lab`。此文件是研究计划的唯一详细正文；Linear [WAR-68](https://linear.app/xiangshushu/issue/WAR-68) 用于状态与资料入口。

## 目标与工作原则

研究**创作判断如何形成、传递、影响下游镜头并经过复检**，而非把 Toonflow、DirectorSKILL、ViMax 直接拼接为新工作流。

- **主线**：DirectorSKILL 原版；Toonflow 作同类机制的知识对照；ViMax 仅在讨论镜头拆解、视觉参考依赖时按需读。
- **研究分类不等于系统架构**：“故事理解、导演意图、表演/调度、镜头设计、制作/验证”只是分析视角，不预设五个 Agent、必经阶段或 Schema。
- **三种对象分开**：创作目标/判断；Skill 提供的方法与知识；画布和保存/调用工具的技术工作流。
- **先提出问题，再阅读必要章节**；不要因为知识库体积变大就全量加载。

## 研究方法：每个机制记录九个问题

1. 它解决什么创作问题，是否对观众体验带来必要价值？
2. 原文哪一处规定？是硬规则、模板、经验建议还是示例？源版本与 SHA 是什么？
3. 输入的剧本事实、用户决定、场景与道具约束是什么？缺少什么？
4. 本阶段输出什么具体判断？哪些是模型凭自身知识补足？
5. 下游是否读到这个判断、如何转换、丢失或新增了什么？
6. 可证伪的增量假设是什么（相对于不使用或局部改变该机制）？
7. 有什么输出、用户反馈、失败或反例？运行条件是否可比？
8. 出错应修改哪个上游环节、怎样复检，不引入新错误？
9. 最终是否值得借鉴？证据不足应暂缓，不因原 Skill 具有该功能就一并采纳。

研究记录严格区分：**源规则、模型自主判断、用户修订、实际观察、解释性推断、未知**。

## 第一批研究问题（C 剧本）

- 故事理解：人物目标、戏剧问题、内外冲突、潜台词、情绪转折是否来自剧本依据？
- 导演意图：从理解故事到“让观众何时知道什么、注意什么、感受什么”，是否有明确的决定或缺口？
- Visual Thesis / Director's Book：前者是否提供可实现的视觉命题，后者是导演的统一摄影视听策略还是过早规定镜头？
- Beat：是否实际改善戏剧压力与信息组织，还是只添加中间表？
- Blocking / Shot Plan：位置、动作、空间距离和镜头功能是否可追溯到上游观众体验目标？
- 风险修复：空间几何、道具状态、接近同景别的切镜、Red/Amber 风险应该从哪里修复，下游能否如实保留与验证？

## 证据等级和设计门槛

| 级别 | 可声称的内容 |
| --- | --- |
| L0 · 源规则 | Skill 说应该做某事；尚未证明效果 |
| L1 · 单次演示 | 某一模型输出符合/不符合要求；不表明由 Skill 独立造成 |
| L2 · 定向修订 | 基线、单点改变与下游变化均可追溯，注明混杂条件 |
| L3 · 跨剧本复验 | 不同类型案例支持某项机制的适用范围，同时收集反例 |
| L4 · 真实生产验证 | 图像/视频/剪辑和人工 QC；**不在本计划默认范围内，另行授权** |

最终研究应说明每个机制所达到的证据等级，哪些信息尚不足以指导设计。绝不把“产出格式完整”直接当成“导演决策有效”。
