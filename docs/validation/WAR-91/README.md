## 4. 最小反馈与停止条件

本轮 V1 **按“发现可追溯反例即可停止，不无限调参凑绿”的授权边界收口**。最值得局部修订而不是重做全场的两件事：

1. **Blocking 对周的观察通道**：保持首次露出阶段林/摄影机/周的信息差，但在蓝夹盖 K 后，周走到桌旁必须可以看到**蓝夹盖住桌面的位置**。需要小范围调整林姿态或周的到桌路径与反应时点，重新测「周见夹」和「首露周未见 K」两条件的同时成立，不能只看 K 的旧遮挡射线。
2. **Blocking 对林的右手取 K**：在不改变 K 位置、左手持蓝夹及单次右手交接的 B 设定下，重新安排林手、肩、躯干的自然可达路线。旧右肩固定姿态硬失败，但不授权改成左手拿钥匙、移动 K、第二次交接。此后才需要补局部 C1 停手连续性/Shot03→04 手物接触及紧邻镜头复检。

若修订影响 B 已批准的重要动作/镜头交付责任，须产生**新的派生局部候选**并按差异交用户重新审阅，不得回写已批准 B 或 WAR-72 冻结样本。

## 5. 镜头一致性的短讨论关口

用户此前要求在任务达到合适阶段时简短讨论镜头相关一致性。本轮已提供真实例子：`K` 是否不移动、蓝夹/纸接触和唯一交接属于**世界/道具事实连续性**；周被林挡住 K 却须看见蓝夹，属于**物理视线＋人物知情**组合；新 Shot01→02 的提纸动作相位、Shot02→03 的松夹/停手、Shot03→04 的右手交接以及主观视角误认属于**镜间观看连续性**。

建议现在只讨论职责边界：**工程校验**追踪 K/手/物/状态和真实切点约束；**Director Agent**负责依据观众知情设计调度和取景替代；**Blender/Canvas/人**负责验证实际几何与观看效果。此次 V1 发现“周不能同时看见蓝夹”不能由单一 Schema 字段或影片生成自动消除。讨论完再决定是先做 Blocking 局部修订复检，还是为 V2 留下明确风险，不提前建立大规模一致性系统。
